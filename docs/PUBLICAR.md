# Publicação no GitHub

Este pacote está pronto para um repositório estático. Ele ainda não representa um site publicado.

## Criar o repositório

1. No seu perfil do GitHub, crie um repositório chamado `mapa-52-semanas`.
2. Para divulgação aberta, selecione público.
3. Inicialize com um README para criar a primeira branch. O README deste pacote poderá substituí-lo depois.
4. Dê acesso ao novo repositório à conexão do ChatGPT, se a instalação estiver limitada a repositórios selecionados.
5. Envie o link do repositório na conversa para que o código seja enviado pelo conector, ou faça o upload dos arquivos manualmente.

## Upload manual

Extraia o ZIP. Envie o conteúdo da pasta `mapa-52-semanas`, com `index.html` na raiz. Preserve `assets`, `docs`, `exemplos`, `scripts`, `tests` e os arquivos de licença. Não envie somente o ZIP: o GitHub Pages precisa dos arquivos extraídos.

Para um caminho mínimo, também é possível renomear o HTML independente para `index.html` e enviá-lo. O repositório completo é melhor para manutenção e documentação.

## Ativar o Pages

Nas configurações do repositório, abra **Pages**. Em publicação por branch, selecione a branch que contém os arquivos e a pasta raiz. Salve e aguarde o endereço que o próprio GitHub informar. Abra esse endereço e confira **Explorar exemplo** antes de divulgar.

Não é necessário workflow de build, servidor, chave de API ou banco. O arquivo `.nojekyll` informa que os arquivos devem ser servidos diretamente.

Referência oficial: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
